# Report spec and secret healing stoppages with retry budget intact

Spec and secret cause failures stopped the healing loop through the same `giveUp` helper as a spent retry budget, so `finishHealing` recorded `Exhausted: true` in the job metadata and the Plane comment claimed "Retry budget exhausted (N of M attempts)" even when no retries had been used. The helper now takes the exhausted flag explicitly: true only when `attempts >= budget+1`, false for spec and secret stoppages. The Needs-attention ticket handoff for those causes was already keyed on the cause, not the flag, and is unchanged.

**What it adds**
- `internal/controlplane/healing.go`: `giveUp` takes an `exhausted` parameter; the budget-spent path passes true, the spec/secret path passes false, so job metadata and the Plane comment no longer claim a spent budget for human-required causes.
- `internal/controlplane/healing_test.go`: `TestHealRunSpecAndSecretDoNotRetry` now also asserts the metadata records `healing.exhausted` false and no Plane comment claims the budget was exhausted.

**What is not implemented**
- Nothing; behavior in all other healing paths (requeue, infra backoff, budget exhaustion) is unchanged.

**What was not tested**
- Live Plane ticket round-trip; covered by the existing fake client assertions in the package tests.

**Tested**
- `go test ./internal/controlplane/ -count=1`: full package passes. Regression check: with the fix reverted, `TestHealRunSpecAndSecretDoNotRetry` fails ("job metadata records exhausted for a spec cause with budget remaining"); with the fix, it passes.
